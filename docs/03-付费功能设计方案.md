# 付费功能设计方案（增强功能激活）

> **状态：设计方案稿，尚未实施。**
> 本文档仅描述方案，不包含任何已落地代码。后续如需实施，请严格按「各文件改动清单」逐项执行。

## 1. 背景与目标

### 1.1 背景

App 功能已基本完备（目标信息监听、警报提醒、计时、分析等）。为了给推广和持续运营提供经济回报，考虑将部分增强功能设为付费项，用户通过**捐款**获得解锁能力。

现状问题：

- 项目里已有微信 / 支付宝收款二维码（见 `html/test_SMS_donate.html`），但**静态收款码无法自动确认用户是否付款**；
- 原页面中的支付宝回调检测（`payByAlipay2` + `checkAlipayCallback`）实际**不可靠**：支付宝转账协议（`actionType=toAccount`）不支持 `returnUrl` 回调，无法据此判断支付结果；
- 因此需要一套不依赖支付回调、可离线校验的付费解锁机制。

### 1.2 目标

- 基础功能**永久免费**，增强功能（震动和闪光的长时长）需激活后才可用；
- 激活采用**人工发激活码 + App 本地离线校验**，无服务器、无支付 SDK、无网络依赖；
- 提供**总开关**，一键切换「免费全开」与「收费模式」，方便随时决定是否启用收费；
- 激活码为**通用激活码**（不绑定设备/机器码），同一时期所有用户共用同一激活码，附带**有效期**（默认 3 个月），到期自动失效，形成可持续续费机制。

## 2. 总体方案

```
用户捐款（微信/支付宝扫码） → 截图/留言给开发者
    ↓
开发者用离线脚本生成通用激活码（含有效期截止日 + 校验码） → 发给用户
    ↓
用户在「更多 → 激活付费功能」页输入激活码
    ↓
App 本地离线校验（格式 + 日期 + FNV-1a 校验码） → 通过则写入有效期
    ↓
首页震动时长放开到 30/60 秒；到期后自动回退免费档
```

要点：

- 激活状态保存在本地 `api.getPrefs`（键 `donateExpire`，值为 `YYYYMMDD`），无需联网；
- 校验算法为纯 JS 实现的 FNV-1a 哈希，不依赖任何第三方库；
- 收费模式关闭时，全部功能直接放开，激活入口隐藏，不影响现有用户体验。

## 3. 总开关（收费模式）

### 3.1 实现方式：代码常量

在新增的 `script/pay-config.js` 中定义：

```js
// true = 启用收费模式（增强功能需激活码解锁）
// false = 免费模式（全部功能直接放开，激活入口隐藏）
var PAY_MODE_ENABLED = false;
```

- **发布决策**：上线前改这一行常量后重新编译即可，无需改业务代码；
- 收费模式下，只有 `isFeatureUnlocked()` 返回 `true`（已激活）才放开增强功能；
- 免费模式下，`isFeatureUnlocked()` 恒为 `true`。

### 3.2 唯一判断入口

所有功能锁定判断统一走：

```js
// 增强功能是否可用
function isFeatureUnlocked() {
    return !PAY_MODE_ENABLED || isActivated();
}
```

业务代码只调用 `isFeatureUnlocked()`，不直接读开关，避免散落判断逻辑。

## 4. 激活码格式与校验算法

### 4.1 激活码格式

```
YB-YYYYMMDD-XXXXXXXX
│  │        └─ 8 位校验码（FNV-1a 哈希前 8 位，大写字母/数字）
│  └────────── 有效期截止日（YYYYMMDD，含当天）
└───────────── 固定前缀 YB
```

示例：`YB-20261116-A3F9K2Q7`（有效期至 2026-11-16）。

- 通用性：校验码只与「截止日期 + 开发者密钥」相关，**不包含设备信息**，同一时期的激活码对所有用户通用；
- 有效期：截止日当天仍有效，次日自动失效（`parseInt(expire) < 今天` 即过期）。

### 4.2 校验算法：FNV-1a

纯 JS 实现，无依赖：

```js
var DONATE_SECRET = 'YOUR_SECRET_HERE'; // 开发者自行设置的密钥，与离线生成脚本保持一致

function genCheck(expire) {
    var s = 'YB-' + expire + '|' + DONATE_SECRET;
    var h = 2166136261;          // FNV offset basis
    for (var i = 0; i < s.length; i++) {
        h ^= s.charCodeAt(i);
        h = (h * 16777619) >>> 0; // FNV prime，>>>0 转 32 位无符号
    }
    var check = h.toString(36).toUpperCase();
    while (check.length < 8) check = '0' + check;
    return check.substr(0, 8);   // 取前 8 位
}
```

注意：`>>> 0` 是关键——JS 数值默认有符号，必须转无符号 32 位整数，否则不同环境下结果不一致。

### 4.3 激活码校验（App 内）

```js
function verifyActivateCode(code) {
    code = (code || '').trim().toUpperCase();
    var m = /^YB-(\d{8})-([A-Z0-9]{8})$/.exec(code);
    if (!m) return { ok: false, msg: '激活码格式不正确' };
    var expire = m[1];
    // 1. 日期校验
    var now = new Date();
    var today = now.getFullYear() * 10000 + (now.getMonth() + 1) * 100 + now.getDate();
    if (parseInt(expire, 10) < today) return { ok: false, msg: '激活码已过期' };
    // 2. 校验码校验
    if (m[2] !== genCheck(expire)) return { ok: false, msg: '激活码无效' };
    return { ok: true, expire: expire };
}
```

校验通过后写入 `api.setPrefs({ key: 'donateExpire', value: expire })`。

### 4.4 开发者离线生成脚本（仅开发者电脑使用）

不放入 App 中，单独保存：

```js
// gen-code.js —— 开发者离线工具
var DONATE_SECRET = 'YOUR_SECRET_HERE'; // 必须与 App 内一致

function genCode(expire) {
    var s = 'YB-' + expire + '|' + DONATE_SECRET;
    var h = 2166136261;
    for (var i = 0; i < s.length; i++) {
        h ^= s.charCodeAt(i);
        h = (h * 16777619) >>> 0;
    }
    var c = h.toString(36).toUpperCase();
    while (c.length < 8) c = '0' + c;
    return 'YB-' + expire + '-' + c.substr(0, 8);
}

// 生成自今天起 n 个月后到期的激活码
function genForMonths(n) {
    var d = new Date();
    d.setMonth(d.getMonth() + n);
    var y = d.getFullYear();
    var m = d.getMonth() + 1;
    var day = d.getDate();
    var expire = '' + y + (m < 10 ? '0' + m : m) + (day < 10 ? '0' + day : day);
    console.log('到期日:', expire, '激活码:', genCode(expire));
}
```

## 5. 功能锁定范围

### 5.1 免费（不锁定）

- 监控功能本身：目标信息监听、列表展示、分析统计等全部基础功能；
- 震动提醒：**0 / 10 秒**两档可用；
- 闪光灯提醒：单次闪烁可用（时长跟随震动时长，≤10 秒）。

### 5.2 付费解锁（增强）

- 震动时长 **30 / 60 秒**两档：未激活时选这两档会被拦截提示，需先激活；
- 闪光灯「循环闪烁」：现有设计 `flashMode = 2` 循环闪烁**复用震动时长**（`html/test_SMS_monitor.html` 中已有注释确认），因此只要锁住震动时长即可同时约束闪光灯长循环，**无需单独改闪光灯逻辑**。

### 5.3 免费 / 付费对照表

| 功能 | 免费模式 | 收费模式-未激活 | 收费模式-已激活 |
|------|----------|-----------------|-----------------|
| 基础监控/列表/分析 | 可用 | 可用 | 可用 |
| 震动 0 / 10 秒 | 可用 | 可用 | 可用 |
| 震动 30 / 60 秒 | 可用 | **拦截** | 可用 |
| 闪光灯循环闪烁 | 可用 | 受限（随震动时长） | 可用 |
| 激活入口 | 隐藏 | 显示「🔑 激活付费功能」 | 显示「✅ 已激活（至 xxxx-xx-xx）」 |

## 7. 开发者运营流程

1. **配置**：上线前改 `PAY_MODE_ENABLED = true`，并设置 `DONATE_SECRET`（与离线脚本一致）；
2. **收款**：用户在捐赠页扫码捐款后，留言/联系开发者；
3. **发码**：开发者运行离线脚本 `genForMonths(3)` 生成激活码，私发用户（同一时期所有用户共用一个码，也可按付款批次更换）；
4. **验证**：用户输入激活码即本地生效；到期自动失效需重新捐款换码；
5. **换码节奏**：建议每期（如每 3 个月）更换新码，避免旧码无限流通；
6. **费用前置**：在捐赠页/激活页文案中明确「增强功能为捐赠解锁，3 个月有效」。

## 8. 边界与注意事项

- **密钥安全**：`DONATE_SECRET` 硬编码于 App 内，被逆向后无法阻止破解者自行生成激活码——这是无服务器离线方案的固有限制。因采用**通用码**，破解后只需维护一个码即可，风险可接受；不依赖云端意味着没有任何强制失效手段，务必配合运营节奏换码；
- **离线校验不防篡改**：用户可自行修改本地 `donateExpire` 存储值，离线方案无法根治，仅作合理门槛；
- **通用码的权衡**：通用码方便，但若被公开传播（发到群/论坛），会在有效期内免费扩散。可接受的缓解：短期有效期（3 个月）+ 定期换码 + 文案声明「请勿公开传播」；
- **日期格式统一**：`donateExpire` 与激活码内日期均为 `YYYYMMDD` 8 位数字字符串，注意拼接时补零；
- **回退逻辑**：收费模式下若已存时长 >10 秒且未激活，加载时必须回退到 10 秒，避免绕过；
- **不改变免费体验**：`PAY_MODE_ENABLED = false` 时行为与现状完全一致，激活入口隐藏，确保不收费时零侵入。

## 9. 未来升级方向（预留，不在本次范围内）

- **按设备码绑定激活码**：若运营需要精确到设备，可扩展为 `YB-<设备码>-<有效期>-<校验码>`，但需用户上报设备码，流程变复杂（用户已明确不希望这样做）；
- **服务端校验 / 支付回调**：若后续接入自建服务或第三方支付回调，可平滑替换 `verifyActivateCode` 为在线接口，App 内接口保持不变；
- **更多付费项**：可扩展「增强分析报表」「去广告」「主题」等，复用 `isFeatureUnlocked()` 框架，按 `featureId` 粒度判断；
- **激活码批量管理工具**：生成带使用记录的表单工具，便于运营统计。
